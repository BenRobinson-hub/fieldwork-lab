When a session crosses replicas

A bounded field investigation into Streamable HTTP MCP session continuity in a multi-replica Higress deployment.

FINDING / 001
QUESTION

What happens when a request reaches a replica that does not own the stateful MCP session?

OBSERVED RESULT · AS REPORTED

Cross-replica session failure was reproduced in a bounded test.

A session created on one Pod could later reach another Pod without the matching in-memory session state, producing upstream 404 / unknown-or-expired-session outcomes.

CANNOT ESTABLISH

Not an exact reproduction of the initially reported Kubernetes 1.30.3 / Higress 2.1.11 environment; not evidence of an upstream fix.

Original technical comment ↗
SETUP / 01

Environment and observed behavior

The public comment reports a full Higress 2.2.4 Helm deployment with two Streamable HTTP replicas. Each replica maintained its own in-memory Mcp-Session-Id state; cross-replica follow-ups could return 404.

CONDITIONRECORDED OBSERVATION
No Higress hashCross-replica 404 / session not found was reproduced.
Service ClientIP affinity7/10 sampled flows returned 404; 7/10 reached a different Pod.
Upstream hash by $remote_addr10/10 sampled flows remained on one Pod and completed; bounded candidate, with NAT distribution risks.
Hash by session headerBootstrap mismatch: 3/10 sampled sessions differed between creator Pod and later hash target.

The counts above are from the published technical comment, not new live measurements by this website.

INTERPRETATION / 02

What the observation suggests

INFERENCEDo not treat as upstream adjudication

A session-dependent flow needs continuity between initialization and subsequent requests. A hash based on the session ID cannot select the same owner during initialization, because that ID is not yet present.

This account illustrates a possible bootstrap-affinity problem, not a universally approved solution. The public comment also records why a source-IP hash has limitations for shared or NATed addresses.

BOUNDARY / 03

What this does not prove

  • It does not exactly reproduce the initially reported Kubernetes 1.30.3 / Higress 2.1.11 environment.
  • It does not prove that any proposed affinity option is correct for every client topology.
  • It does not establish an accepted upstream patch or a present-day verdict for newer Higress versions.
  • The source comment describes a bounded reproduction, not an independently downloadable full raw test archive on this site.
